# Рабочий контур памяти и CodePy

`Pipeline` объединяет три замороженных пути: лучшую текстовую SSM с pointer (seed 23), семантическую память v5 и сертифицированные программы CodePy local-completion 20/20. Отдельный ранее обученный KV-кодек хранит исполняемые команды и аргументы. Новое обучение не требуется.

## Универсальный режим по парам

Новый цикл не требует именованного контракта и не обращается к `tasks.py`:

```python
result = session.develop(
    X_train=X_train, Y_train=Y_train,
    X_holdout=X_holdout, Y_holdout=Y_holdout,
    entity='клары', property='основная книга', handle='морской атлас',
    values=execution_inputs,
)
```

Математический смысл задают **только пары вход → целевой выход**. Необязательный `task='любая метка'` служит ключом каталога; его имя не выбирает функцию ошибки или проверяющий алгоритм. Без метки создаётся идентификатор учебного набора. Изменение метки при тех же парах не меняет поиск.

В новом режиме все массивы — конечные `np.float32` формы `(N,L)`, где `L>=2`; ширина TRAIN, HOLDOUT и исполняемых аргументов должна совпадать. Число строк может различаться и не обязано равняться 64/7041. Цели должны сохранять мультимножество входных значений. Противоречивые ответы на одинаковый вход и пересечения TRAIN/HOLDOUT отвергаются до поиска; `+0` и `-0` считаются одинаковыми входами для проверки пересечений.

`examples.BlockSearch` получает только копию TRAIN-пар. Он использует общую ошибку несоответствия целям и строит цепочку парных вызовов поиском по префиксам. На каждом шаге сохраняются 32 разных поведения на TRAIN; готовой схемы сортировки/разворота в инициализации нет. `max_calls` задаёт длину до 64 вызовов; `populations` в новом режиме ограничивает число расширений фронта до 95. HOLDOUT не передаётся поиску, и после ошибки сертификации повторного поиска нет.

Отдельный `examples.Verifier` исполняет одного зафиксированного кандидата на **всех предоставленных** парах TRAIN/HOLDOUT, сверяет целевые выходы, мультимножества и побитовое согласие JAX/NumPy. В сессию v4 сохраняются программа с её размерностью, обе выборки, сертификат и геометрия многостраничной памяти. При перезапуске проверка повторяется на сохранённых парах; подмена одного `passed` не помогает.

CLI принимает в операции `develop` поля `X_train`, `Y_train`, `X_holdout`, `Y_holdout` вместо прежнего `examples`; `task` необязателен. Пример: `artifacts/example_development_20261101/demo_request.json`.

Старый вызов `develop(task, examples, ...)` сохранён как отдельный совместимый режим именованных контрактов. Совместимые v1/v2/v3-сессии загружаются и мигрируют; новые проверки по парам не вызывают старые оракулы. При загрузке старых именованных расширений используется их прежний способ проверки, при загрузке расширений по парам — только сохранённые пары.

Полный экзамен нового режима:

```sh
./scripts/python-ci -m research.codepy.ssm_dispatch.examples_exam --output-dir artifacts/my_fresh_example_exam
make ci
```

Проверка `base_commands_matching_training == 0` означает, что для каждой из 96 базовых команд найден вход-свидетель, на котором она расходится с новой задачей. Это исключает переименование любой базовой функции, но не означает мировую научную новизну или доказательство поведения на всех возможных входах.

Произвольными могут быть метка, пары и ширина вектора, а не вычислительные возможности исполнителя: остаются сохранение значений, два открытых парных блока и конечный бюджет поиска. По умолчанию предел цепочки зависит от ширины; для больших ширин задавайте явный `max_calls` в диапазоне 1–64. Непредставимая или неоднозначная по данным задача получает отказ; нейронные веса не обучаются.

## Векторы длины 5, 8 и многостраничная KV-память

В режиме по парам можно передать `X_train.shape == (N,5)` или `(N,8)` и задать `max_calls=16`. Поиск и независимый NumPy-исполнитель используют таблицу всех упорядоченных пар индексов для фактической ширины вектора. Локальные блоки и их r0/r1 не меняются: каждый получает свою пару, возвращает её в общую ленту и обнуляет локальное состояние. Принятая программа хранит свою `arity`; другой размер аргументов отвергается.

Одна страница по-прежнему содержит ID команды и четыре 32-битных аргумента. Вектор разбивается на `ceil(L/4)` страниц, затем страницы всех логических строк разбиваются на физические батчи по 128 записей. ID повторяется на каждой странице, неиспользуемый хвост заполняется нулями. Для длин 5 и 8 нужны две страницы, для длины 9 — три. SHA-256 проверяет всю упорядоченную последовательность страниц; после чтения дополнительно проверяются совпадение ID и размерности команды. Исходные float32 не кодируются через текст и не меняют битов.

Замороженный `numeric_step` и веса KV-кодека не расширяются и не переобучаются: меняется только число его независимых страниц. Сессия v4 сохраняет логическую ширину, число страниц и физических чанков. Для прежних записей без этих полей восстанавливаются ширина 4 и одна страница; нейронные массивы сохраняются побитово.

Чтение использует тот же обученный нейронный декодер, но обрабатывает три независимых банка параллельно и объединяет до восьми физических чанков за вызов. SHA-256, проверка всех ID, размерности и конечности чисел выполняются после каждого чтения. Третий банк завершает чтение после пяти полей; оставшиеся пять читаются только первыми двумя банками, с тем же состоянием и последовательностью токенов. Для простого durable-KV кодека фиксированные переходы M[t] = P[t] @ M[0] + C[t] теперь предвычисляются из текущих весов, включая малые коэффициенты записи/стирания. Скрытое состояние SSM вычисляется рекуррентно; 25 выходов проецируются только в base96 и сразу проходят argmax в том же JIT. Быстрый путь требует точного сброса ключа, ожидаемого предыдущего токена и конечных состояний; иначе применяется прежний core.forward. Аргументы и результаты не кэшируются; формат страниц, запись `numeric_step` и сохранённые массивы не меняются. Историческая реализация сессий v7 принимается по точному прежнему SHA-256 и проходит полную проверку при загрузке.

Базовые команды 0–95 остаются четырёхэлементными. Программа для другой ширины создаётся через `develop()` и получает новый ID; применять старую четырёхэлементную команду к восьми числам не разрешается.

```python
result = session.develop(
    X_train=X5, Y_train=Y5, X_holdout=H5, Y_holdout=T5,
    max_calls=16,
    entity='клары', property='основная книга', handle='морской атлас',
    values=H5,
)
```

Полный экзамен: `./scripts/python-ci -m research.codepy.ssm_dispatch.variable_exam --output-dir artifacts/my_variable_exam`. Он использует sort5, reverse5, reverse8 и попарное упорядочивание восьми элементов на пяти зафиксированных библиотеках/кодеках, проверяет память, отказ, прежний эталон и перезапуск. Найденная sort5 содержит девять ненулевых вызовов. Это подтверждение на переданных примерах и проверочном пакете, не доказательство универсальной обучаемости произвольных задач или эффективности хранения больших наборов в нейросостояниях.

## Запуск

Из корня проекта:

```sh
./scripts/python-ci run_codepy.py --seed 0 --session .ci-output/demo.session.npz --request request.json
make ci
```

Нужен установленный `uv`. Обёртка автоматически выбирает Python 3.12 и устанавливает зафиксированные зависимости из `requirements-ci.lock` в кэш uv. JAX запускается на CPU, включая дочерние процессы. Проектовые веса не меняются; проверочный вывод CI направляется в `.ci-output/`.

Пример `request.json`:

```json
[
  {
    "operation": "remember",
    "entity": "клары",
    "property": "основная книга",
    "handle": "морской атлас",
    "command": 0,
    "arguments": [[3, -1, 2, 0]]
  },
  {"operation": "observe", "text": "За окном шёл дождь. На берегу реки стоял дом."},
  {"operation": "execute", "question": "Что именно относится к Кларе: главное издание? Ответ:"}
]
```

Ответ содержит ID команды, восстановленные из памяти аргументы, результат `[[-1, 0, 2, 3]]`, согласие JAX/NumPy и следующий токен текстовой SSM. Следующий запуск с тем же `--session` восстанавливает все три нейронных состояния и память чисел. Сессии пишутся вне неизменяемого `artifacts/`.

## Интерфейс и данные

```python
from research.codepy.ssm_dispatch.pipeline import Pipeline

session = Pipeline(seed=0)  # seeds 0..4
session.remember(entity, property, handle, command, float32_array)
session.observe(text)
execution = session.execute(question)
session.save(path)
session = Pipeline.load(path, seed=0)
```

`entity` передаётся в буквальной форме родительного падежа, как при записи факта v5. `property` — записываемое название свойства. `handle` — короткое буквальное значение; оно не имеет встроенного значения алгоритма. В примере «морской атлас» обозначает сортировку только потому, что это назначение записано операцией `remember`. При другой записи тот же ответ может обозначать вращение и другой массив аргументов.

v5 получает обычный факт «У клары основная книга — морской атлас». Ответ на смысловой вопрос выбирает handle. Исполняемый payload хранится отдельно в **непрерывном KV-состоянии SSM**: ID команды и четыре числа в каждой строке. Каждое число сохраняется как 32-битное представление float32, разбитое на пять символов base96. Три нейронных банка вмещают пять uint32-полей одной строки. Словарь хранит адреса, размеры и контрольную сумму; исходные числа и команда в нём не сохраняются.

`execute()` не принимает аргументы и не выводит алгоритм из формулировки вопроса: он читает ID и числа из памяти. Восстановленная лента передаётся существующему CodePy ABI. Программы сами загружают ячейки в r0/r1; локальные блоки и регистровые результаты обрабатываются тем же интерпретатором, что в сертификатах. NumPy независимо повторяет исполнение, по умолчанию на каждом запросе.

ID `0..95` — четыре семейства × 24 перестановки входа. Базовые команды: **0 sort4, 24 reverse4, 48 rotate4, 72 descending4**. Остальные ID применяют соответствующую программу к переставленным аргументам с обратной перестановкой результата. Все программы загружаются из `codepy_local_completion_20261101`; встроенных реализаций алгоритмов в рабочем исполнителе нет.

Для Python-интерфейса нужны непустые конечные массивы `np.float32` формы `(N,4)`. CLI явно переводит JSON-числа в float32. Повторная запись handle заменяет команду и аргументы. Незарегистрированный handle вызывает `UnknownKey`, неправильный ID/формат или повреждённый payload — `ValueError`; исполняемой подстановки по умолчанию нет.

Сессия содержит версию схемы, seed, хеши моделей, библиотеки и реализации. Несовместимая версия отвергается до исполнения. Запись атомарная, без pickle и без включения весов. Сессия рассчитана на одного владельца; одновременная запись несколькими процессами не поддерживается.

## Границы

Это совместная работа отдельных замороженных моделей, не слияние их весов. Текстовая SSM ведёт причинный языковой контекст и предсказывает следующий токен; решение о handle принимает v5. Англоязычная SSM не получает новых знаний русского языка от подключения v5. Числовые команды явно регистрируются пользователем; произвольное понимание инструкции «напиши новую программу» не добавлено.

Наследуются ограничения v5: короткие именные конструкции, максимум 16 BPE-токенов в значении, знакомые элементы языка, конечные 512 слотов и возможные ошибки семантического чтения. Неизвестный текстовый запрос может быть ошибочно распознан самой нейросетью; строгий отказ гарантирован для отсутствующего ключа payload, а не для всех возможных формулировок естественного языка. Обработка конфликтов синонимических записей не расширялась. Код ограничен четырьмя числовыми элементами; конечный экзамен не заменяет доказательство над всеми float32. Самостоятельное обучение/постановка задач не включены.

## Замкнутый цикл программного улучшения

Контур теперь умеет сам пройти цепочку `пробел → синтез → независимая проверка → публикация → запись в память`. Веса нейронных моделей при этом заморожены.

```python
result = session.develop(
    'pairwise_order4', training_inputs,  # 64 конечных float32-вектора формы (64,4)
    entity='клары', property='основная книга', handle='морской атлас',
    values=execution_inputs,            # аргументы будущего выполнения, форма (N,4)
)
# Только result.status == 'accepted' означает публикацию новой программы.
session.observe('На берегу реки стоял старый дом. ' * 100)
result = session.execute('Что именно относится к Кларе: главное издание? Ответ:')
session.save('.ci-output/my.session.npz')
```

Поддержанные математические контракты: `minmax4`, `rotate_right4`, `partition4`, `pairwise_order4`. Их точные определения переиспользованы из `subtask_discovery/transfer/tasks.py`: это описания нужного поведения, а не готовые программы. Примеры состоят из входных векторов; ошибка кандидата вычисляется только на них по выбранному контракту. Для нового произвольного математического смысла пока нужно добавить декларативный контракт и независимый проверяющий критерий; система не угадывает его из одного названия.

Метод проверяет отсутствие имени задачи в каталоге сессии или неполное совпадение привязанной команды с учебными примерами. В отчёте отдельно указаны уже существующие базовые команды, которые подходят к примерам. `rotate_right4` математически совпадает с базовым `rotate4`; сортировка также удовлетворяет контрактам `minmax4` и `partition4`. Новая регистрация имени не объявляется открытием нового алгоритма. Даже для этих имён проверочный цикл выполняет новый синтез из блоков, не копируя прежнего победителя.

Поиск использует два ранее найденных блока своего seed — перестановку и упорядочивание пары. Он строит шестизвенную программу из случайной популяции тем же CodePy, что в исследованиях. Лимит — 95 популяций по 256 кандидатов; инициализация, мутации и отбор получают только 64 учебных примера. Готовые победители прошлых новых задач в инициализацию не поступают.

После возврата одного зафиксированного кандидата отдельный `Verifier` создаёт полный пакет из 7041 входа, проверяет отсутствие точных совпадений с TRAIN, согласие JAX и NumPy, выполнение контракта и сохранение всех чисел. Результат проверки не используется для повторного поиска: провал означает `rejected`. Метод возвращает журнал стадий и причину отказа.

Успешная публикация транзакционная: новая команда, смысловая привязка v5, числовая KV-запись и таблица задач сначала создаются в изолированном состоянии сессии; исходная сессия меняется только после успешной записи. Любая ошибка проверки или записи оставляет прежние программы и память на месте. Новые ID начинаются с 96 и добавляются в каталог конкретной сессии; неизменяемый базовый каталог 0–95 не редактируется.

Сессия версии v2 сохраняет тела принятых программ, сертификаты, происхождение и таблицу задач вместе с нейронными состояниями. При загрузке новые программы повторно проходят полную независимую проверку; одного поля `passed: true` из файла недостаточно. Предыдущие совместимые v1-сессии мигрируют с сохранением памяти и всех прежних команд, при точном совпадении известных версий моделей и исходной реализации. Неизвестные версии отвергаются.

В JSON CLI добавлена операция `develop`: поля `task`, `examples`, `entity`, `property`, `handle`, `arguments` соответствуют аргументам метода. `populations` можно уменьшить до 1–95; при неуспехе программа не публикуется. Пример полного запроса: `artifacts/self_development_20261101/demo_request.json`.

Полный экзамен всех четырёх контрактов на пяти seeds:

```sh
./scripts/python-ci -m research.codepy.ssm_dispatch.development_exam --output-dir artifacts/my_fresh_development_exam
make ci
```

`make ci` включает сквозной тест нового цикла, заведомо неверный TRAIN-идеальный кандидат, повреждённый файл программы, отказ записи, исправление неполной привязки, сохранение/загрузку и миграцию старой сессии. Полный экзамен дополнительно проверяет прежние 20/20 после добавления новых команд.

## Иерархическая композиция по примерам (схема v6)

`Pipeline.develop(..., X_train=..., Y_train=..., X_holdout=..., Y_holdout=..., use_macros=True)` добавляет к парным блокам программы, уже независимо сертифицированные в этой сессии. Необязательный `macro_commands=[96,97]` фиксирует разрешённые источники; без него используются все совместимые программы сессии. В JSON CLI доступны те же поля. Старый режим по умолчанию и именованные контракты сохранены.

Вызываемая программа получает подмассив по выбранным различным индексам; результат записывается в те же позиции. Поддерживаются окна и несмежные подмассивы, в том числе 4-элементные навыки на лентах длины 8 и 16. Формат допускает произвольный порядок индексов. Поиск перебирает возрастающие сочетания и окна, с бюджетом 4096 размещений на навык; при большом пространстве оставляет до 128 лучших макроразмещений на каждый источник по исходному TRAIN. Фронт — 64 поведения на слой стоимости, верхняя цепочка до 64 вызовов, глубина вложенности до 8 уровней и развёртка до 4096 парных вызовов. Нахождение решения в этом конечном бюджете не гарантируется.

Каждый принятый навык содержит неизменяемые снимки зависимостей, хеши и исходные сертификаты. Проверяющий сначала перепроверяет зависимости, затем новый кандидат на отдельном HOLDOUT. JAX разворачивает адреса макровызовов в парные инструкции; NumPy независимо собирает подмассив, вызывает вложенную программу и возвращает результат. Повторяющиеся/неверные индексы, подмена зависимостей, несогласие исполнителей и провал контрольных пар запрещают публикацию. Проверочные пары никогда не поступают в поиск.

Сессия v6 сохраняет граф зависимостей и повторно сертифицирует его при загрузке. Известные v1–v5 поддерживаются без изменения исходных файлов и нейронных массивов. Восстановление float32 из KV побитовое; 8 и 16 элементов используют соответственно 2 и 4 страницы на строку. Это не расширяет числовые гарантии старого исполнителя: его ограничение диапазона и обработка субнормальных значений сохраняются. Сертификация проверяет фактический переданный набор, включая точное согласие JAX/NumPy и мультимножества.

Воспроизводимый экзамен с одинаковыми учебными парами для плоского и иерархического поиска:

```sh
./scripts/python-ci -m research.codepy.ssm_dispatch.hierarchy_exam --output-dir artifacts/my_fresh_hierarchy_exam
make ci
```

Число вызовов верхнего уровня измеряет компактность описания программы. Также сохраняется число развёрнутых парных вызовов; компактное описание само по себе не означает ускорения.


## Бюджет развёрнутых парных операций

В иерархическом режиме `max_pair_ops=21` ограничивает полную стоимость цепочки. Метрика `certificate['unrolled_pair_ops']` рекурсивно считает ненулевые элементарные парные вызовы внутри всех использованных макроблоков; `expanded_pair_calls` сохраняется как совместимое имя той же величины. Число верхних вызовов отражено отдельно в `calls`. Лимит включён в язык программы и проверяется также сертификацией и при исполнении.

Поиск строит фронты по этой стоимости, а не по верхним шагам. Макроблок sort4 платит за все свои 5 парных операций, лёгкий pairwise_order4 — за 2, точечный вызов — за 1. Точная цепочка выбирается на первом успешном слое; среди одинаковых поведений учитывается компактность верхнего описания. Фронт из 64 поведений остаётся конечным: глобальная оптимальность не обещается. Максимум верхних вызовов `max_calls` действует одновременно. Без явного `max_pair_ops` бюджет равен `max(6, L*(L-1)//2)` для ширины L; максимум явного бюджета — 4096. `populations` ограничивает число слоёв до 95.

Программы sort4, pairwise_order4 и другие источники сначала должны быть получены и сертифицированы штатным циклом сессии. Поиск не извлекает алгоритм из их имён; он использует тела команд и учебные пары новой задачи. Для каждого источника выделена собственная квота размещений, чтобы лёгкие навыки оставались доступны наряду с полными макроблоками. На прежних данных sort8 для всех пяти seeds найдены цепочки с 21 парной операцией вместо 26; число верхних вызовов — 12–15 против 21–23 у плоских программ.

Режим сертификатов `hierarchical-v2` хранится в сессии v6. Для прежних `hierarchical-v1` оставлен побитово тот же проверяющий в `hierarchy_v1.py`; старые сертификаты не переписываются. Старый принятый навык можно использовать как зависимость новой программы. Если повторный вызов `develop()` задаёт более строгий бюджет, уже зарегистрированная программа переиспользуется только когда укладывается в него; иначе запускается поиск, и при отказе старая команда/память сохраняются.

Полный экзамен стоимости на прежних неизменённых TRAIN/HOLDOUT:

```sh
./scripts/python-ci -m research.codepy.ssm_dispatch.cost_exam --output-dir artifacts/my_fresh_cost_exam
make ci
```

Тот же параметр поддерживается в JSON CLI: `"use_macros": true, "max_pair_ops": 21`. Метрика относится к исполнению программы: более широкий поиск и получение исходных навыков требуют дополнительных вычислений. Уменьшение числа парных операций не является измерением ускорения по времени.

## VerifierCache в штатном execute (схема v7)

`Pipeline.execute(verify=True)` использует `VerifierCache`: SHA-256 всего каталога и вложенных зависимостей, версии и владельца сессии, смысловых привязок, семантического состояния и метаданных/контрольных сумм KV. На промахе создаётся отдельный снимок и повторяется полный сертификат, включая корневую программу; перед публикацией SHA должен остаться тем же. На попадании выполняются быстрые проверки хешей и происхождения, но тяжёлая сборка не повторяется.

Вопрос каждый раз проходит через SSM/v5, аргументы заново декодируются из KV и проверяются по контрольной сумме, затем заново исполняются JAX и независимый NumPy. Кэш не хранит ответов, аргументов или нейронных весов. Новые режимы по примерам/иерархии проверяют побитовое согласие; числовая семантика старых базовых и именованных контрактов сохранена.

Успешные записи `remember`, чтение нового текста `observe`, загрузка и копирование сессии сбрасывают подготовку; прямые изменения словарей каталога/привязок обнаруживаются на следующем обращении. Ошибки и расхождения очищают кэш. Временный текстовый carry обычного `execute` не входит в ключ: код от него не зависит. Максимум — восемь проверяющих; кэш никогда не сохраняется в NPZ. Известные сессии v1–v6 по-прежнему загружаются с холодным кэшем и точной проверкой прежних версий.

Повторные CPU-измерения всех пяти seeds, включая чередующийся некэшированный контроль на той же памяти: `artifacts/verifier_cache_20261101/REPORT.md`. Для новой иерархии одиночные sort8/reverse16 занимают около 27/26 мс вместо 279/296 мс; пакеты8192 — около1.10/2.12 с вместо1.36/2.41 с. Значения — медианы по seeds; точные парные отношения, первые вызовы и разброс сохранены в отчёте. Выигрыш относится к прогретым чтениям без записи; после сброса полная сертификация остаётся.

```sh
./scripts/python-ci -m research.codepy.ssm_dispatch.performance.latency --output-dir artifacts/my_fresh_cache_latency --uncached-control artifacts/verifier_cache_20261101/pipeline_uncached.py
make ci
```


## Полный диапазон float32

Рабочий `Pipeline.execute(verify=True)` исполняет исходный байткод без обрезания
к ±1e6. JAX хранит числовые слова в uint32, включая субнормальные значения;
сложение округляется как binary32. Независимый `numpy_runtime.py` выполняет
те же инструкции обычными NumPy-операциями без числового ограничения.
Сравнение выходов всегда побитовое. Входы NaN/Inf и неконечный выход
отклоняются; переполнение сложения не заменяется насыщением.

Старые сертификаты по-прежнему проверяются исходным ограниченным исполнителем.
Это сохраняет их происхождение, а не доказывает правильность произвольной
программы на всех float32. Полноразмерные sort8/reverse16 дополнительно проверены
на всех пяти seeds и границах конечных порядков. Инструкционное `-0 + +0`
даёт `+0` и в JAX, и в NumPy; исходные биты в KV остаются неизменными.

Хеш независимого NumPy-исполнителя входит в версию сессии и ключ VerifierCache.
Прежние известные сессии v1–v7, включая версию исправления субнормальных чисел,
загружаются без перезаписи файлов с холодным кэшем.

Обычные входы без отрицательного нуля и значений ниже безопасной сетки
используют аппаратное сложение. Проверка диапазона делается на каждом вызове:
суммы и целые константы замкнуты на сетке 2^-126, поэтому субнормальный
результат в этом пути невозможен. Остальные входы используют точное
целочисленное сложение; лента в обоих путях хранится побитово.
