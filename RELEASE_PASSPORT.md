# Паспорт релиза Memory + CodePy 1.0.0

Дата: 2 ноября 2026 года. Тег: `memory-codepy-v1.0.0`.
Ветка: `codex/memory-codepy-release-20261102`.
База: `07f07ea` основной исследовательской рабочей папки. Это отдельный локальный релиз памяти и CodePy; он не является новой версией ветки `aethergate` с эволюцией и мониторингом.

## Назначение и штатный контур

`run_codepy.py` → `Pipeline` → замороженные текстовая SSM с pointer (seed 23), семантическая память v5 и нейронный KV-кодек → сертифицированные программы CodePy → независимая проверка NumPy.

Контур запоминает смысловое назначение, ID команды и числовые аргументы; по вопросу восстанавливает их из состояния памяти и выполняет команду. Сессии сохраняются атомарно без pickle. Готовая библиотека содержит sort4, reverse4, rotate4, descending4 с перестановками входов. Поддерживаются разработка программ по примерам, векторы переменной ширины и иерархические программы. Разработка программ меняет код и состояние сессии, а не нейронные веса.

## Состав и происхождение

- Исходники взяты как отдельный снимок основной рабочей папки; исходная папка не очищалась и не переключалась. Во время упаковки параллельно изменились `research/codepy/ssm_dispatch/pipeline.py`, `test_codepy_development.py`, `test_codepy_verifier_cache.py`. Эти более поздние изменения оставлены в исходной папке и не подмешаны в проверяемый снимок релиза.
- `release/imported-sources.json` — исходные контрольные суммы перенесённых файлов до правок переносимости релиза.
- `release/frozen-assets.json` — SHA-256 готовых весов, библиотек, протоколов, исходных снимков и тестовых сессий. Эти входы включены в Git явно; весь старый каталог артефактов не переносится.
- `requirements-ci.in` и `requirements-ci.lock` фиксируют CPU-зависимости; запуск через `scripts/python-ci` выбирает Python 3.12 с помощью `uv`.
- Исторические абсолютные пути сертификатов разрешаются внутри текущего дерева; байты сертифицированных библиотек и весов сохранены. Загрузка старых сессий допускает только явно перечисленные версии и проверяет модель, seed, библиотеку и программы.

## Запуск

Нужен установленный `uv`; при первом запуске может понадобиться интернет для Python и зависимостей. CPU; GPU не требуется.

```sh
make ci
./scripts/python-ci run_codepy.py \
  --session .ci-output/demo.session.npz \
  --request release/example-request.json
```

Пример записывает массив `[3, -1, 2, 0]` под смысловым назначением, задаёт вопрос и возвращает отсортированный массив `[-1, 0, 2, 3]` с `independent_agrees: true`. Для повторного чистого примера выберите новое имя файла сессии. Подробности API: `research/codepy/ssm_dispatch/PIPELINE.md`.

## Проверка без обучения

`make ci` в этом релизе проверяет память, CodePy, независимость проверки, повреждения данных, сохранение/загрузку и совместимость исторических сессий, точность float32, кэши и восстановление команд/аргументов. До и после тестов проверяются контрольные суммы замороженных входов. Обновления Adam и `train_step` в процессе тестов запрещены; попытка делает проверку неуспешной. Обращения основного процесса тестов к исходной рабочей папке также запрещены.

Исторический `verify_system.py` включает обучение и не запускается этим `make ci`. Он доступен отдельно через `make verify-research`; полный исторический контур доступен через `make ci-research`; в рамках подготовки этого релиза его не запускали. Большие исследовательские экзамены и новое обучение не проводились.

Машинный результат проверки сохраняется в `.ci-output/release-verification.json`, журнал — `.ci-output/make-ci.log`; эти рабочие файлы не включаются в Git. Итоговая запись проверки поставляется отдельно в `release/verification.json`.

## Ограничения

Это исследовательский числовой исполнитель с ограниченным языком программ и проверяемой памятью, не универсальная языковая модель. Историческое «20/20» относится к записанному протоколу библиотеки, а не к любым задачам. Один файл сессии рассчитан на одного владельца; конкурентная запись не поддерживается. Входы — конечные float32; ограничения формата проверяются. `observe` меняет состояние памяти, не веса модели.

Исходный релиз зафиксирован тегом `memory-codepy-v1.0.0` (коммит `6861dea`). Для публикации ветка дополнительно объединена с `aethergate`; добавлен маршрут GitHub Actions без обучения. Тег исходного проверенного релиза не перемещается. Публикация ветки и тега и PR выполняются отдельно; слияние PR и создание GitHub Release не входят в эту публикацию. Старые артефакты и изменения в исходных рабочих деревьях сохраняются.

## Исправление при публикации PR

Первый Linux-прогон обнаружил зависимость знака нуля в независимом NumPy-исполнителе от SIMD-реализации `minimum`/`maximum`. В ветке публикации правило для двух нулей закреплено явно: минимум имеет отрицательный знак, если он есть хотя бы у одного операнда; максимум — только если оба операнда отрицательны. Проверки остаются побитовыми. Добавлен тест, воспроизводящий выбор второго операнда при равенстве независимо от процессора. Нейронные веса и замороженные сертификаты не изменены. Исходный опубликованный тег остаётся неизменным; исправление поставляется в PR поверх него.
